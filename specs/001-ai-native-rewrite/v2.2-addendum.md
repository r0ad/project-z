# v2.2 增量规格：AI 全量数据操作与多会话

> 本文件是 `spec.md` / `plan.md` 的增量补充，不改变 v2.0 的核心闭环与本地优先原则。
> 状态：已实现并通过 Windows 实测；待发布 v2.2.0。

## 1. AI 副驾操作全部本地数据

### 用户故事

- 作为用户，我可以在「问问点点」里用自然语言查询和管理项目、里程碑、执行日志、AI 分析、知识库，而不需要逐页点击。
- 作为用户，当我要求新增/修改/删除/完成某件事时，点点直接调用写工具并展示确认卡，不在正文里再问一遍「是否确认」。
- 作为用户，确认卡用名称描述操作，例如「将项目「跨端工作台」的里程碑「三端验收」标记为完成」，不出现内部 ID。
- 作为用户，我点「先不改」时数据保持不变；点「同意并执行」后才真正写入。
- 作为用户，我可以在历史对话里继续之前的话题，也可以随时新开对话。

### 功能需求

1. 工具白名单固定为 23 个，覆盖 `projects`、`milestones`、`project_logs`、`ai_insights`、`knowledge_entries`、`tags`、`knowledge_tag_links`、`project_knowledge_links`、`favorites` 与工作区概览；不得开放任意 SQL 或文件系统工具。
2. 只读工具（`list_*` / `get_*`）自动执行，结果回传模型，最多 4 轮；写工具必须先写 `ai_tool_calls`（`pending`）并展示确认卡。
3. 确认卡摘要由 `ProjectTools.summarize` 异步解析名称：项目名、里程碑名、日志所属项目+日期、知识标题；ID 只用于参数与执行，不得展示给用户。
4. 用户确认后逐条执行，写审计 `completed` / `failed`，并把工具结果回传模型生成最终回复；拒绝写 `rejected`，不修改数据。
5. 确认卡展示期间禁止继续发送新消息；输入框禁用。
6. 所有工具调用必须可在 `ai_tool_calls` 追溯：工具名、参数、结果摘要、耗时、状态。
7. 系统提示要求：用户已明确要求写操作时直接调用工具，确认由界面卡片负责；缺少必要信息时才先提问，不编造 ID。

### 验收

- `test/data/project_tools_test.dart` 覆盖 23 个工具定义、读写标记、项目/里程碑/日志/知识 CRUD、异步名称摘要与错误返回。
- Windows 实测：创建项目 Alpha → 确认卡「创建项目「Alpha」」；添加里程碑 M1 → 确认卡带项目名与里程碑名；删除项目 Alpha → 确认卡「删除项目「Alpha」」；知识创建/删除同样按标题展示。
- 只读 `list_projects` 不出现确认卡，直接返回项目列表。

## 2. 聊天体验

### 功能需求

1. 聊天消息列表使用 `reverse: true`，进入会话默认在底部；短会话也贴底，不因内容少而悬空。
2. 只有用户本来在底部（距底 < 96px）时才自动跟随新消息；用户上翻阅读时不强制拉回。
3. 流式正文与推理过程分开展示；有 reasoning 时显示「正在思考…」摘要，有正文后显示「生成中…」。
4. 多会话：历史对话底部弹层，展示标题、相对时间、当前会话标记；支持切换继续、新开、删除（删除前确认）。
5. 新会话发送后立即出现在历史列表；删除当前会话时回到空态，不残留待确认工具或流式文本。
6. `ChatState.copyWith(resetConversation: true)` 是唯一能清空 `conversationId` 的方式，避免 `??` 保留旧值。

### 验收

- `test/features/chat/chat_state_test.dart` 覆盖会话重置不继承流式内容。
- Windows 实测：历史弹层可在 3 个会话间切换；新对话发送后立即入列；长回复默认贴底；删除项目/知识确认卡均按名称展示。

## 3. 非目标

- 不暴露原始 SQL、数据库表名或内部 ID 给模型/用户。
- 不做任意第三方工具、MCP 接入或插件系统；工具白名单保持最小。
- 不做多用户、云同步或跨设备会话同步。
- 不做聊天「停止生成」按钮（仍在路线图）。
