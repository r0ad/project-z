# 功能规格：点点 · AI-native 个人项目工作台（Flutter 重写）

- 规格版本：1.0.0
- 状态：Draft（待旧版审计结果回填）
- 对应宪法：`specs/constitution.md`
- 目标平台：Windows / Android / iOS

## 1. 背景与目标

「点点」是一个本地优先的个人项目管理工具，旧版基于 uni-app + SQLite，核心闭环是
**设定目标 → 记录执行 → AI 分析 → 沉淀知识库**。

旧版存在三类问题：页面与数据层耦合、AI 只作为孤立的「按钮功能」、以及大量历史遗留交互。
本次不是在旧代码上修补，而是用 Flutter 重建一套**同一工作流、更新设计、AI-native** 的应用：

1. 数据仍然完全本地，单用户，离线可用；AI 是可选的增强，不是运行前提。
2. AI 从「一个聊天页」升级为贯穿全流程的协作层：能理解当前项目上下文、能调用本地工具、
   输出结构化结果，并由用户确认后落库。
3. 一套代码自适应手机与桌面，Windows / Android / iOS 功能对齐。
4. 工程按 SDD + TDD 推进：规格、计划、任务、测试都可追溯。

## 2. 用户与使用场景

**目标用户**：有多个长期目标（学习、写作、独立开发、健身等）的个人；愿意用 AI 降低
记录与复盘成本，但在意数据隐私；可能在电脑上规划、在手机上随手记录。

**典型一天**：

- 早上打开桌面端，看到「今日聚焦」：3 个活跃项目、2 个到期里程碑、1 条 AI 风险提示。
- 通勤时在手机上用一句话记录：「今天把登录页做完了，进度大概 60%，明天接支付」，
  AI 拆成进展/问题/计划，用户确认保存。
- 晚上桌面端让 AI 做本周复盘：总结产出、指出停滞项目、建议下周 3 件事，
  并把可复用的经验沉淀成知识卡。
- 周末在知识库问：「我之前解决 Flutter 构建慢的问题用了什么方案？」，
  AI 基于本地知识回答并给出引用。

## 3. AI-native 设计原则（产品层）

| 原则 | 产品表现 |
|---|---|
| 每步都有 AI 入口 | 新建项目、记录日志、写知识、做复盘都有「AI 帮我起草/整理」 |
| 自然语言进，结构化出 | 一句话 → 项目草稿 / 日志三栏 / 知识卡；落库前可编辑 |
| 上下文自动编排 | 副驾知道当前页面、当前项目、最近日志、相关知识 |
| 工具可执行 | 副驾能查数据、建项目、记日志、改里程碑，但写操作必须确认 |
| 引用可追溯 | AI 结论标注来源（日志日期、知识标题、里程碑） |
| 失败可降级 | 无 Key / 断网 / 模型错误时，手动流程完整可用 |
| 人保持控制 | 不自动改目标、不自动删数据、不自动发布 |

## 4. 用户故事与验收场景

### US-1 首次启动与 AI 配置（P1）

作为新用户，我希望在 2 分钟内完成启动并知道下一步做什么。

验收：

1. Given 首次安装，When 启动，Then 显示 3 页以内 onboarding：产品价值 → 数据本地说明 →
   AI 配置（可「稍后配置」）。
2. Given 选择配置 AI，When 选择供应商并粘贴 Key，Then 可「测试连接」，成功显示模型与延迟，
   失败给出可操作错误（Key 无效 / 网络 / base_url）。
3. Given 跳过 AI，When 进入首页，Then 所有手动功能可用，AI 入口显示「配置后可用」而非报错。
4. Given 已完成 onboarding，When 再次启动，Then 直接进入首页，不再重复引导。

### US-2 创建项目与 AI 目标拆解（P1）

作为用户，我希望用一句话描述目标，让 AI 生成可执行的项目与里程碑。

验收：

1. Given 首页，When 点「新建项目」，Then 可选「AI 帮我拆解」或「手动创建」。
2. Given 输入「三个月内上线我的 Flutter 应用，每周至少 10 小时」，
   When 生成，Then 返回：项目标题、SMART 目标描述、5–8 个里程碑（含建议日期），
   每个字段可编辑、可删除、可重排。
3. Given AI 返回非法 JSON，When 解析失败，Then 自动重试一次；仍失败则展示原始文本并
   允许重试/改用手动，不阻塞创建。
4. Given 用户确认，When 保存，Then 项目与里程碑在同一事务写入，进度按里程碑推导为 0%。
5. Given 未配置 AI，When 进入新建页，Then 展示手动表单与模板库，不出现不可用按钮。

### US-3 记录执行（P1）

作为用户，我希望用最低成本记录今天做了什么。

验收：

1. Given 任意页面，When 点全局「记录」按钮，Then 打开快速记录面板，默认今天、默认最近项目。
2. Given 输入一段自然语言，When 点「AI 整理」，Then 拆成「进展 / 问题 / 计划」三栏，
   可逐栏编辑后保存；无 AI 时三栏可手动填写。
3. Given 语音输入可用，When 按住说话，Then 转文字填入正文，失败时保留已输入内容并提示。
4. Given 日志保存成功，When 返回项目详情，Then 时间线与统计立即更新，项目「最近更新」变化。
5. Given 日志关联里程碑，When 用户勾选「完成某里程碑」，Then 进度按已完成/总数重算；
   达到 100% 时项目状态自动变为已完成。
6. Given 同一天重复记录，Then 允许多条，按时间倒序展示，不覆盖。

### US-4 项目详情与里程碑（P1）

作为用户，我希望在一个地方看清目标、进度、日志与 AI 洞察。

验收：

1. Given 项目详情，Then 桌面端为「左列表 + 右详情」或宽内容区，手机端为单列 + 顶部返回。
2. 详情包含：概览（目标、状态、进度、日期）、里程碑、日志时间线、AI 分析、知识关联。
3. Given 勾选/取消里程碑，Then 进度即时变化；全部完成时提示并自动置为已完成；可手动改回进行中。
4. Given 删除项目，Then 二次确认，级联删除里程碑、日志、分析、对话、关联，但**不删除**已沉淀的知识。
5. Given 项目为空（无日志），Then 空状态引导「记录第一条」或「让 AI 帮我写第一条」。

### US-5 AI 分析与周复盘（P2）

作为用户，我希望 AI 基于真实记录给出有价值的复盘，而不是泛泛而谈。

验收：

1. Given 项目有 ≥1 条日志，When 生成分析，Then 输出：进展摘要、风险/阻塞、下步建议、
   建议关注的里程碑；每条结论尽量引用日志日期。
2. Given 选择「本周复盘」，Then 汇总本周所有项目日志，生成周报：完成事项、停滞项目、
   时间分布、下周 3 个建议；可保存为 summary。
3. Given 分析生成中，Then 流式展示并可取消；取消后不落库。
4. Given 分析已保存，Then 可编辑、删除、复制；项目详情按时间倒序展示。
5. Given AI 不可用，Then 可生成「本地统计版复盘」（无 AI 文案），保证功能不消失。

### US-6 知识沉淀（P2）

作为用户，我希望把项目中的经验变成可检索、可复用的知识。

验收：

1. Given 一条日志或一次分析，When 点「沉淀为知识」，Then AI 生成标题、正文、3–5 个标签建议，
   用户可编辑并关联来源项目。
2. Given 手动新建知识，Then 支持标题、Markdown 正文、标签、关联项目、收藏。
3. Given 知识列表，Then 支持关键词搜索（标题/正文/标签）、标签筛选、收藏筛选、排序。
4. Given 知识详情，Then 展示正文、标签、关联项目、相关知识和「问这条知识」入口。
5. Given AI 建议的知识与已有知识高度相似，Then 提示「可能重复」并展示已有条目，
   用户可选择合并/仍然新建。
6. Given 删除知识，Then 同步清理标签映射、项目关联、收藏；不影响来源日志。

### US-7 全局 AI 副驾（P2）

作为用户，我希望随时问「点点」，它能理解我现在在做什么，并帮我操作。

验收：

1. Given 任意主页面，Then 右下角/侧边有副驾入口；桌面端可固定为右侧栏，手机端为全屏 sheet。
2. Given 在项目详情打开副驾，Then 首条上下文包含当前项目、里程碑、最近 7 天日志摘要。
3. Given 提问「这个项目哪里卡住了」，Then 回答引用具体日志与里程碑；无足够数据时明确说「记录不足」。
4. Given 用户说「帮我记一条：今天完成了登录页」，Then 副驾调用 `add_project_log` 工具，
   展示待确认卡片（项目、三栏内容、日期），用户确认后才写入。
5. Given 用户说「把里程碑 2 标记完成」，Then 展示确认卡片；确认后进度更新，副驾复述结果。
6. Given 工具调用失败或参数不合法，Then 不写入，说明原因并给出修正建议。
7. Given 对话历史，Then 按会话持久化，可重命名、删除、清空；支持停止生成与重新生成。
8. Given 无 AI 配置，Then 副驾入口可用但提示配置；不崩溃。

### US-8 首页与统计（P2）

作为用户，我希望打开应用就知道今天该关注什么。

验收：

1. 首页包含：问候与日期、今日聚焦（到期/停滞项目）、快速记录、最近动态、AI 今日建议（可选）。
2. Given 有到期里程碑，Then 首页置顶提醒；点击直达项目。
3. Given 统计页，Then 展示：近 30 天日志数、活跃项目数、完成里程碑数、连续记录天数、
   每周活动柱状图、项目进度分布；数据全部本地计算。
4. Given 无数据，Then 展示引导而非空白图表。

### US-9 设置与 AI 供应商（P1/P2）

作为用户，我希望自由选择模型供应商，并确保 Key 安全。

验收：

1. 设置包含：外观（浅色/深色/跟随系统）、AI 供应商、数据与备份、关于/更新、隐私说明。
2. Given AI 设置，Then 内置供应商预设（2026 年最新模型列表）+ 自定义 OpenAI 兼容端点；
   可保存多套配置并激活一套。
3. 可配置：显示名称、base_url、model、temperature、max_tokens、超时；Key 单独安全存储。
4. Given 测试连接，Then 发起最小请求并显示延迟/模型回显；失败区分鉴权、网络、模型不存在。
5. Given 删除配置，Then 同步删除安全存储中的 Key；激活配置删除时自动切换到可用配置或未配置态。
6. Given 导出诊断信息，Then 不含 Key、正文，仅版本/平台/错误码。

### US-10 备份、恢复与导入导出（P3）

1. Given 设置 → 数据，When 导出备份，Then 生成带 schema 版本与时间戳的 JSON 文件（可选 zip），
   通过系统保存/分享面板选择位置。
2. Given 导入备份，Then 先校验格式与版本，展示将覆盖/新增的数量，二次确认后事务导入。
3. Given 版本不兼容，Then 拒绝并说明原因，不破坏现有数据。
4. Given 导出单项目 Markdown，Then 生成包含目标、里程碑、日志、分析的 Markdown 文件。

### US-11 三端体验（P1）

1. Windows：可调整窗口，最小 960×640；支持键盘快捷键（新建 Ctrl+N、搜索 Ctrl+K、记录 Ctrl+L）；
   标题栏与窗口状态记忆（尺寸/位置/最大化）。
2. Android：返回键行为正确；安全区适配；深色状态栏；APK 可安装。
3. iOS：完整工程、图标、启动屏、Info.plist 权限文案；CI macOS 可 `--no-codesign` 编译。
4. 响应式：<600 手机单列 + 底部导航；600–1024 紧凑；>1024 桌面 NavigationRail + 双栏。
5. 同一功能在三端数据格式一致，备份可跨端恢复（不含平台专属路径）。

### US-12 更新与关于（P3）

1. 关于页展示版本、构建号、开源许可、隐私政策、项目主页。
2. 检查更新：读取可配置的 `version.json`，比较语义版本，提示下载页；不自动下载安装。
3. 更新源可配置，默认项目站点；GitHub 仅作归档，不作为国内默认下载源。

## 6. 非功能需求

- **性能**：冷启动到首页 < 2s（中端 Android）；1 万条日志下列表滚动 60fps；
  搜索 < 200ms；数据库操作不阻塞 UI isolate。
- **可靠性**：写操作事务化；迁移有测试；崩溃不丢已提交数据；导入失败回滚。
- **隐私**：默认不联网；AI 请求前展示上下文范围；Key 不入日志/备份/导出。
- **可访问性**：动态字体、语义标签、对比度 AA；键盘可达；触控目标 ≥44dp。
- **国际化**：首版中文；文案集中管理，为后续英文预留。
- **可维护性**：分层依赖单向；`flutter analyze` 零 issue；核心领域测试覆盖率 ≥80%。

## 7. 数据与迁移

- 全新安装，不迁移旧版 SQLite（用户已确认）；旧版数据可通过导出 JSON 后人工参考。
- 新 schema 由 Drift 管理，版本从 1 开始；每次变更附 migration + 测试。
- 实体：项目、里程碑、日志、AI 分析、AI 总结、知识、标签、知识-标签、项目-知识、
  收藏、对话、消息、AI 配置、设置、AI 工具调用审计。
- 单用户，无 `users` 表；个人资料存 `settings`。
- 删除策略：项目删除级联其里程碑/日志/分析/对话/关联，但保留知识；知识删除级联标签映射/关联/收藏。

## 8. 非目标（本期不做）

- 云同步、多设备实时同步、多人协作、账号体系。
- Web / 小程序端。
- 从旧版数据库自动迁移。
- 分享码 / 推广码激活 AI。
- GitCode 云备份、应用内自动下载安装 APK。
- 自建模型推理、本地 LLM。
- 复杂甘特图、看板拖拽、时间追踪计时器。

## 9. 成功标准

1. 新用户 3 分钟内完成「建项目 → 记一条 → 看到进度/分析」。
2. 所有 P1 验收场景有自动化测试或明确手工验证记录。
3. `flutter analyze` 零 issue，`flutter test` 全绿，Windows/Android/iOS CI 构建通过。
4. 断网、无 Key、模型 500 三种情况下核心手动流程可用。
5. 仓库无密钥、无构建产物、无旧 uni-app 源码。

## 10. 开放问题

- 默认内置哪些供应商与模型（待 `docs/research/ai-providers-2026.md` 回填）。
- 是否内置一个免 Key 的「本地模板模式」作为 onboarding 默认（倾向：是）。
- 桌面端是否支持多窗口（倾向：本期单窗口）。
- 知识全文搜索是否升级为向量检索（倾向：本期 FTS5，预留 embedding 接口）。
